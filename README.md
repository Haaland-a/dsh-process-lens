# 过程讲解器（dsh-process-lens）

把 AI 干活的每一步摊开给你看：**原文点一下就看全文**（不花额度），**人话解说按需生成**（点哪步才讲哪步），**用哪个模型讲由你单独挑**。

它回答的是那个最常冒出来的问题：*"这半天它到底在忙什么？"*

---

## 一、你要的三件事

### 1. 讲解员可以单独选模型

插件有自己的一条模型路由，**不跟主对话绑在一起**。

- 打开面板 → 设置区「讲解模型」下拉框 → 选供应商 + 模型；
- 默认 `跟随会话（deepseek / chat）` 会实时显示主对话现在用的是哪个，方便对照；
- 选完立刻生效，下一个要讲的步骤就用新模型；右边「刷新」可重新读一遍模型列表；
- 下拉框的提示 `只影响讲解，不影响会话本身用的模型` 就是它的边界。

省钱的一般做法：主对话用强模型干活，讲解模型挑一个又便宜又快的。

### 2. 花不花额度、看哪几轮，你自己点

**默认一个字都不自动讲。** 打开面板只是把原文摊出来，一次模型调用都没有。

| 你想干的事 | 点哪儿 | 花多少 |
| --- | --- | --- |
| 看它这一步到底做了什么 | 卡上「▸ 展开原文」，展开是**全文**：完整思考、完整参数、完整返回、它说的话 | 0 |
| 只看某一步的人话解释 | 那张卡右下角 `讲这步` | 1 次 |
| 把这一轮还没讲的都讲一遍 | 面板顶部 `全部讲一遍（N 步）`，N 是还没讲过的步数 | N 次 |
| 想重讲 | 讲过的卡按钮变 `再讲一次` | 1 次 |

讲过的步骤会标成 `讲完了`，「全部讲一遍」自动跳过它们，不重复烧钱。

**打开时显示 N 步**（设置区第三行，默认 8）：一进来只摆最近 N 步，省得一屏刷不完、也方便直接看最新的；上面有一行 `上面还有 X 步没摆出来 · 展开这一轮全部 Y 步`，点一下全给，再点 `收起` 回到最近 N 步。**不会只给你 3 步**——想看多少有多少，只是默认先摆最近的。

「自动弹出」开关（默认关）：开了以后只要出现新一轮就把面板摊出来——**摊出来也只是给你看原文，不会自动讲**。

**打开时自动讲 N 步**（设置区第四行，默认关）：开了以后，每次你打开面板，插件会自动把**最近 N 步**（默认 3，可填 1–20）翻成人话概要摆出来，你点开就有东西看，不用一步步点「讲这步」。代价是每次打开都花 N 次模型调用；已经讲过的步会被跳过，不会重复收钱。

- 关着（默认）：一打开只显示原文，一分不花，想看哪步点哪步。
- 开着：打开即有概要；同一轮里已经讲过的不会再讲，重新打开时只补没讲过的。
- 想临时只讲一步：不管这个开关，直接点那张卡的「讲这步」。

### 3. 反馈只说人话

每张卡两层：上面是**默认折叠的原文**（点开就是全文，不是节选），下面是三行人话：

```
标题      改配置读取顺序
在做什么   把默认档和立即档的判断先后调了个头，先看有没有人在看
结果      改完了，现在默认不花额度
```

- 工具名翻成人话：`grep` → 搜代码，`write` → 写文件，`pwsh` → 跑命令……
- 失败会标红并写明原因（`权限不足`、`文件不存在`……），不是甩一串堆栈。
- 讲失败也不静默：卡上直接写 `这次没翻译出来，可以再点一次`。

### 4. 面板尺寸

右下角浮动，**620 宽 × 面板高度的 74%（上限 780px）**，避开窗口右上角的 − □ ×；正文 13px，原文块可以滚动，长内容不再挤成一条。

## 二、三个入口在哪儿

| 位置 | 长什么样 | 干什么 |
| --- | --- | --- |
| 每条回答下方 | 小按钮「过程」 | 看这一轮的过程（最常用） |
| 输入框下面 | 小按钮 `看过程` | 不离开对话就能看最新一轮 |
| 页面浮层 | 右下角浮动面板 | 完整过程、选模型、逐条点讲 |

面板里可以一路往下翻历史轮次——**插件装上之前的轮次也能看**（会从会话自己的事件流里回放补账，不需要你重新问一遍）。

## 四、遇到问题

| 现象 | 怎么办 |
| --- | --- |
| 点「过程」提示「刷新一次页面」 | 浏览器半更新了，`Ctrl+R` |
| 提示「插件后端没在跑」 | 重启 DSH，或在插件页重新启用一次 |
| 模型下拉里只有「跟随会话」 | 面板里点「刷新」；仍为空会直接显示读不到的原因 |
| 卡片上只有标题没有原文 | 正常，原文默认折叠，点「▸ 展开原文」 |
| 只看到最近几步 | 默认摆最近 N 步（设置里可改），点「展开这一轮全部」看全 |
| 讲解很慢 | DeepSeek 思考档位高，插件已自动降到最低档；换更小的模型更快 |

## 五、实现要点（给以后的自己看）

- **Host 半**：监听 `session/event` 记账（轮次、步骤、工具调用、思考、回答），
  `GET /process-lens/stream`（SSE）推送 `snap` / `card` / `turn` / `ping`；
  `GET|POST /process-lens/api/*` 处理配置、模型目录、轮次定位、快照与讲解请求。
- **原文全文**：`cardOf()` 的 `raw = { thinking, answer, actions[{name,label,detail,args,state,output}] }`，
  文本统一用 `FULL_CHARS = 20000` 截（实际等于不截），`tool.result` 记账时也不再用 `oneLine` 压平，
  只有喂给讲解模型的那份 prompt 才走 `REASONING_CHARS / ANSWER_CHARS / RESULT_CHARS` 的节选。
- **花钱闸门**：`enqueue(sessionId, turn, step, force)`——`force !== true` 时只把状态标 `idle` 并推一帧，
  **绝不排队**。只有 `POST /explain` 走 `enqueue(..., true)`；SSE 连上只算「看」，不算「讲」。
  `/explain` 不传 `step` 时过滤掉 `done / running / queued`。
- **打开时显示 N 步**：`settings.recent`（默认 8，1–100），前端只 slice 后 N 步渲染，另给「展开全部」按钮；
  这是纯前端行为，不影响 host 记账，也不影响讲解。
- **讲解预算**：并发 2，单次 60 秒超时，`maxTokens` 默认 1600；
  `llm.stream` **不能传 `purpose`**（`LlmRequestPurpose` 是 `never`），
  且必须显式取 `resolveModelInfo().reasoning.efforts` 的最低档，否则思考会把预算吃光。
- **历史补账**：第一次被问到某会话时，回放 `session.snapshotEvents()` 末尾 4000 条事件；
  回放期间**不触发**讲解。
- **鉴权**：路由统一过 `ctx.get('connection').requestRejection(req)`。
- **设置持久化**：`<DSH_PROFILE_DIR>/process-lens.json`。

## 六、自测

```bash
node harness.mjs
```

用假 ctx 跑 30 条断言：历史补账、messageId→轮次定位、工具人话标签、原文（含参数/返回）随卡返回、失败标红、
「只连流不点 = 0 次模型调用」、显式点讲才 1 次且用插件自己选的模型、讲失败会标 `failed` 并推流、
「全部讲一遍」跳过讲过的、`recent` 默认值与上下限、`autoSummarize` 开关与 1–20 上限。不联网、不花额度。
