[![DSH plugin](https://img.shields.io/badge/DSH-plugin-4f7cff)](https://github.com/Haaland-a/dsh-process-lens)
[![version](https://img.shields.io/badge/version-0.8.0-2ea043)](./package.json)
[![license](https://img.shields.io/badge/license-MIT-blue)](./LICENSE)
[![self test](https://img.shields.io/badge/self--test-134%2F134-2ea043)](./harness.mjs)

把 AI 干活的每一步摊开给你看：**原文点一下就看全文**（不花额度），**人话解说按需生成**（点哪步才讲哪步），**用哪个模型讲由你单独挑**。

它回答的是那个最常冒出来的问题：*"这半天它到底在忙什么？"*

---

## 一、你要的几件事

### 1. 讲解员可以单独选模型

插件有自己的一条模型路由，**不跟主对话绑在一起**。

- 打开面板 → 设置区「讲解模型」下拉框 → 选供应商 + 模型；
- 默认 `跟随会话（deepseek / chat）` 会实时显示主对话现在用的是哪个，方便对照；
- 选完立刻生效，下一个要讲的步骤就用新模型；右边「刷新」可重新读一遍模型列表；
- 下拉框的提示 `只影响讲解，不影响会话本身用的模型` 就是它的边界。

省钱的一般做法：主对话用强模型干活，讲解模型挑一个又便宜又快的。

### 2. 花不花额度、看哪几轮，你自己点

**默认一个字都不自动讲。** 打开面板只是把原文摊出来，一次模型调用都没有。

| 你想干的事 | 点哪儿 | 花多少 |
| --- | --- | --- |
| 看它这一步到底做了什么 | 卡上「▸ 展开原文」，展开是**全文**：完整思考、完整参数、完整返回、它说的话 | 0 |
| 只看某一步的人话解释 | 那张卡右下角 `生成讲解` | 1 次 |
| 把这一轮还没讲的都讲一遍 | 面板顶部 `全部讲一遍（N 步）`，N 是还没讲过的步数 | N 次 |
| 想重讲 | 讲过的卡按钮变 `再讲一次` | 1 次 |

讲过的步骤会标成 `已生成`，「全部生成」自动跳过它们，不重复烧钱。

**打开时显示 N 步**（设置区第三行，默认 8）：一进来只摆最近 N 步，省得一屏刷不完、也方便直接看最新的；上面有一行 `上面还有 X 步没摆出来 · 展开这一轮全部 Y 步`，点一下全给，再点 `收起` 回到最近 N 步。**不会只给你 3 步**——想看多少有多少，只是默认先摆最近的。

「自动弹出」开关（默认关，也建议关）：开了以后只要出现新一轮就把面板自己弹出来，正在读别的东西就会被它打断，所以推荐关着——想看再点「看过程」。

**打开时自动讲 N 步**（设置区第四行，默认关）：开了以后，每次你打开面板，插件会自动把**最近 N 步**（默认 3，可填 1–20）翻成人话概要摆出来，你点开就有东西看，不用一步步点「讲这步」。代价是每次打开都花 N 次模型调用；已经讲过的步会被跳过，不会重复收钱。

- 关着（默认）：一打开只显示原文，一分不花，想看哪步点哪步。
- 开着：打开即有概要；同一轮里已经讲过的不会再讲，重新打开时只补没讲过的。
- 想临时只讲一步：不管这个开关，直接点那张卡的「生成讲解」。

### 3. 反馈只说人话

每张卡两层：上面是**默认折叠的原文**（点开就是全文，不是节选），下面是三行人话：

```
标题      改配置读取顺序
在做什么   把默认档和立即档的判断先后调了个头，先看有没有人在看
结果      改完了，现在默认不花额度
```

- 工具名翻成人话：`grep` → 搜代码，`write` → 写文件，`pwsh` → 跑命令……
- 失败会标红并写明原因（`权限不足`、`文件不存在`……），不是甩一串堆栈。
- 讲失败也不静默：卡上直接写 `这次没翻译出来，可以再点一次`。

### 4. 面板尺寸

右下角浮动，**620 宽 × 面板高度的 74%（上限 780px）**，避开窗口右上角的 − □ ×；正文 13px，原文块可以滚动，长内容不再挤成一条。

### 4.5 两个标签：过程 / 设置

面板顶上分出两页，不用再在过程上面挤一排开关：

- **过程**：你让它做的事、这一轮的每一步、生成讲解 / 全部生成；
- **设置**：外观、讲解模型、自动弹出、显示几步、自动讲、讲解口味、提示词存档。

设置页自己会滚，提示词预览再长也整段看得到（之前「提示词显示不全」就是这么修掉的）。

### 4.6 「思考」开关（默认关）

设置页第二行是「思考」开关，**默认关**：

| 状态 | 实际发生什么 |
| --- | --- |
| 关（默认） | 不传思考档位里偏高的那些，能拿到 none / off / minimal 就用它，拿不到就用最低档；回答更快、更省额度 |
| 开 | 不干预档位，让模型用自己默认的那一档先想再写；讲得更细，但慢一些、更费额度（预算会自动抬到 2400 token 起，避免还没写完就被截断） |

一句话：平时关着够用；哪一步实在看不懂，再打开让它多想一会儿。

### 4.7 过程页：最近 N 步 / 全部（老会话也能看全）

过程页顶上有个小开关：**「最近 N 步」 / 「全部 M 步」**。

- 刚进来默认「最近 N 步」（N 在设置里改，默认 8），屏幕不炸；
- 点「全部 M 步」就把这一轮每一步都摆出来，**选完会记住**，下次打开还是你选的那个；
- 中间还有一条「上面还有 X 步没摆出来 · 展开这一轮全部 Y 步」，点一下同样切到全部。

以前已经结束的老会话（甚至 DSH 重启过的那种）只显示最后几步，是因为补账只回放最近 4000 条事件——
现在点开某一轮时，插件会**从这一轮的 turn/start 重新回放**，把整轮补齐（每一轮只补一次，不重复花钱也不重复算）。

### 4.8 读的时候不被打断（新）

以前一边看一边有新步骤进来，会撞两件事：一是「最近 N 步」那个窗口往前滑，你正在看的那张卡被挤出屏幕，
连「展开原文」都跟着合上了；二是有时滚动条被拽到最底下。现在两件都不发生了。

- **往上翻一下就自动钉住**：面板记下「此刻最新是第几步」，后面新来的步骤只在下面排队，上面的卡片一张不动。
- **点「展开原文」也会钉住**：你要读这一步的完整参数/返回，它就老老实实待在那儿。
- **不再弹提示条**（v0.4.0 改）：以前顶上会冒一条「后面又做了 N 步——没打断你」加一个「回到最新」按钮，纯属多一句话；现在这些步骤静静地排在下面，不吭声。
- **自己滑到底 = 想跟着看新的**，会自动解钉继续跟；换一轮、换会话也自动恢复跟随。

一句话：手不动，面板就不动；滑到底它才继续往下跟。

### 4.9 开着就自动讲（新）

设置里新加了一个开关 **「开着就自动讲」**（默认关）：打开它以后，**只要面板开着、并且停在过程页**，
每出现新的一步就自动把这一步翻成人话——不用你一下一下点「生成讲解」。

三道闸门保证不会偷偷烧额度：

- 开关没开 → 什么都不做；
- 面板关着，或者你切到了「设置」页 → 立刻停，后台不会继续讲；
- 刚打开面板时**只记基线、不补讲历史**，所以打开那一刻不会一口气冒出七八次模型调用；
  打开时正在跑的那一步，跑完照样自动讲。

另外每次快照最多只排 **2 步**，避免一轮结束突然攒了十几步一起排队；剩下的随时点「全部讲一遍」补上。
顶部提示条会明确写着「已开『开着就自动讲』：面板开着的时候来一步讲一步（花额度），关掉面板就停」。

### 4.10 省 token++：每 N 步才找一次模型（新）

你说的「每 n 轮发给模型一次这几步骤的总结」就是这个。原来那档「省 token」其实只做了一件事：
**把发给模型的内容压短**——调用次数一步都没少。这一档是把**调用次数**降下来。

设置里两行：

| 行 | 干什么 | 推荐 |
| --- | --- | --- |
| 省 token++ | 开着以后平时不吭声，**每攒够 N 步才找一次模型，一次把这 N 步合起来讲** | 推荐 5 |
| 后台跑 | 关着：只有面板打开时才跑，一关面板就停；开着：面板关着也照常攒着讲 | 关 |

算一笔账：一轮 10 步，一步一步点要 **10 次调用**；每 5 步一讲只要 **2 次**。
单次提示词也短了——不用每步都重复一遍前文那几步。

**它怎么工作的**

1. 平时只记账，不调模型；
2. 攒够 N 步 → 只给最末那步排一次讲解，提示词里明说「第 3~7 步一共 5 步，合起来讲一次，不要逐条复述」；
3. 这 N 步里前面的几步在界面上标成「已并进第 7 步的总结」，卡片角上写「第 3~7 步合并」；
4. 讲到的那张卡照旧三行字，讲的是这几步的**整体**：合起来在干什么 / 一起做了哪些关键动作 / 合起来的结果；
5. 一轮结束时（`turn/end`）剩下的步会顺手攒成最后一批讲掉，不留白；
6. 这一批要是讲失败了，合并标记会**退回单步**（变回「生成讲解」），不会留下半截看不出状态的卡。

**和省 token++ 冲突的两个开关**

「打开时自动讲」「开着就自动讲」都是**一步一讲**，和「攒够再一次」正好相反：两个一起开，
批量省下的额度当场又花回去。所以开着省 token++ 时，设置页会出一条黄条：

> 和省 token++ 冲突：「打开时自动讲」「开着就自动讲」会一步一步单讲，把批量省下来的额度又花回去。　[把这两个关掉]

点一下就同时关掉那两个，不用自己找。客户端里这两个 effect 也在批量开着时直接短路，
就算存档里还留着开的状态，也不会偷偷单讲。

**后台跑：默认关**

关着的时候，Host 会看「现在有没有面板连着」——没人看就一步都不跑（`viewers === 0` 直接返回）。
所以平时挂机、关掉面板去干别的事，一分额度都不会花。想让它在你不在的时候也照样攒着讲，才把这个打开。

**三个坑已经处理掉了**

- 批量开着时**不再单步自动讲**（`if (batchEveryOf() < 2) enqueue(...)`），否则每步单讲一遍，等于白省；
- 「每 N 步」是真的攒够 N 步才动（`list.length < every` 就返回），不是每两步就凑一批；
- 换一轮从第 1 步重新数（`record.batchedTo` 按轮次记），不会把上一轮的尾部并到新的一轮里。

### 4.11 重新讲一遍：同一件事，换一份提示词再讲一次（新）

每张卡的右下角多了一个 **重新讲一遍**。点开它会掉出一个菜单，挑一份就能重讲：

| 菜单项 | 意思 |
| --- | --- |
| 用当前设置 | 按设置里那份风格再来一次（这一项会写出当前用的是哪份，例如「用当前设置（现在是「专业」）」） |
| 我的存档 | 你在提示词工作台里存过的每一份，点哪个用哪个 |
| 内置风格 | 通俗 / 专业 / 一句话 / 给新手 |

关键点：**选哪份只影响这一次**。设置里选中的风格不会被改掉，下次自动讲解照旧用你原来那份。
讲完卡片角上会多一枚紫色小签，写的就是这次用的那份名字，一眼能看出这句人话是谁的口吻讲的。

四个已经处理掉的地方：

- **已经讲过的也能重讲**：`enqueue(..., again = true)` 绕过「讲过了就跳过」那道判断，不然按钮点了没反应；
- **旧的三行先留着**：重讲期间按钮显示「重讲中…」，上面那段旧讲解不清空，等新的到了才替换，不会闪成空白；
- **失败了不清空**：新的一次没讲成，旧的正文还在，只是状态变「讲失败」，可以换一份或者用同一份再试；
- **批量合并的步也能重讲**：`preset` 和 `batched` 互不影响，被并进第 7 步的第 3 步，照样能单独挑一份讲。

实现上只有两处改动：客户端 `POST /explain` 多带 `{ replay: true, preset }`；Host 用 `personaOf(preset)` 解析
`s::<内置风格>` / `p::<存档 id>`，再走 `systemPromptWith(job.preset)` 拼这一次的 system——不写回设置文件。

### 4.12 省 token 到底怎么省：一次实测（新）

一句话：**它不改你说话，只改「发多少字给模型」**。开与关都是同一次调用、同三行输出，区别只在这一份提示词有多长。

拿一段真实味的材料在本机跑了一遍（12 步：反复读同一个日志、跑两次构建、改三处、再跑测试；每一步都带一段很长的内部思考）：

| 步骤 | 关（原文） | 开（精炼） | 实际用的是 | 省了 |
| --- | --- | --- | --- | --- |
| 1 | 1031 字 | 525 字 | 精炼版 | 49% |
| 2 | 948 | 602 | 精炼版 | 36% |
| 3 | 893 | 681 | 精炼版 | 24% |
| 5 | 948 | 817 | 精炼版 | 14% |
| 8 | 893 | 720 | 精炼版 | 19% |
| 12 | 890 | 843 | 精炼版 | 5% |
| **合计 12 次调用** | **11240 字** | **8938 字** | 12 次调用一次没少 | **20%** |

**为什么前面省得多、后面省得少**：精炼版会把「最近 N 步」压成一行骨架（默认 5 行），这个骨架差不多是固定成本；轮次越往后，这 5 行占的比例越高，所以第 1 步能省一半，第 12 步只剩 5%。**调用次数始终没变**——想少调用，用上面的「省 token++」。

同一件事，两份提示词的差别长这样：

```text
【关】这是这一轮里的第 12 步。
助手在这一步的内部思考（节选）：先看第 12 步到底改了什么。我先把这段日志从头过一遍……（整段 400 多字）
这一步调用过的操作：
- 跑命令（npm test） → 返回：[info] 21:01:00 reading E:/…/user-profile-handler.ts (pass 1) [info] …

【开】这是这一轮的第 12 步。省 token 模式：最近 5 步已精炼成骨架……
- 第8步 跑命令：command=npm run build → error: #1:12 deprecated import / done
- 第11步 跑命令：command=npm run build → build ok: 0 error, 0 warning / done
- 第12步★ 跑命令：command=npm test → tests: 42 passed, 0 failed / done
  它在想：问题是 handler 里直接取了 profile.id，而上游可能返回 undefined，所以要先加空值判断。
图例：#1=E:/Personal/Desktop/proj/src/server/handlers/user-profile-handler.ts
```

读得出来四件事：

1. **长路径折成 `#1`**，图例只在最后写一次——同一段路径出现 10 次也只占 4 个字符。
2. **样板行被丢掉**，只留「有信息」的两行（报错 / 结论），并且按原顺序还原，不会前后颠倒。
3. **思考只抽带结论味的那一句**（「问题是…所以…」），不把整段独白搬过去。
4. **连着几步干同一件事只写一行**，写成「第 5~7 步（同样的事做了 3 次）」。

**两个质量修正（本次一起改了）**：

- 抽句以前把英文句号也当句末，`profile.id` 会被劈成「……profile.」+`id，而上游……`，读起来像话说到一半。现在只在**真句末**断句，中文标点一律算，英文标点必须后面跟空格或结尾。
- 挑行以前「有数字」就加分，于是 `[info] 21:00:00 reading …(pass 1)` 这类样板行会挤掉 `tests: 42 passed, 0 failed` 这样的结论行。现在样板行先扣两分。

**「关」也不是全文——这点要说清楚**：原文版给工具返回**也只留第一行 240 字**（思考 1600、回答 700、诉求 300），并不是把原始日志整段搬过去。所以两档的差别不是「全 vs 缺」，而是**截断方式**：

| | 怎么取 | 实测结果 |
| --- | --- | --- |
| 关 | 按**原文顺序**取前面的字 | 2342 字日志里，关键线索在第 21 行 → **丢了**，发出 541 字 |
| 开 | 按**重要性**挑行（报错 / 数字 / 结论 / 首末行） | 同一份日志 → **留下了**那句「这个失败只在北京时间下午四点以后出现」，发出 464 字 |

反过来说也成立：如果关键那行**既没有数字、也没有报错/结论词**，精炼版会漏掉它，而原文版因为按顺序保留开头，反而可能留住。两种方式各有盲区，所以提示词里写死了护栏：**「只看要点，缺的信息就说「看不到」，别猜」**——宁可告诉你没看到，也不许编。

**你看到的原文没被压**：卡片上的「展开原文」走的是另一条路（上限 20000 字），不经过上面任何一道压缩。压缩只发生在「发给模型的那一份」里。

**顺手修的记账重复（v0.3.3）**：同一轮被「边发生边记」过一次、又被深扫重放过一次时，同一次工具调用会被记成两条，卡片上就冒出「共 2 次」和一行假的「还在进行」。现在完整的一轮跳过重放，重放过的记录按「调用 id + 工具名」合并（保结果、补状态），自测也加了这条。

**怎么自己验**：面板 →「提示词」页签，右上角就写着「现在这份 XXXX 字 / 不省 token 要 YYYY 字」。想对比就把「省 token（精炼）」关掉再看一眼，数字是现算的。

### 4.13 v0.4.0：更准、更干净、浅色真的浅（新）

**① 讲得更准。** 提示词里加了一节「准确性（比好听更重要）」，五条硬规矩：

| 规矩 | 管住什么 |
| --- | --- |
| 名词照抄原文 | 文件名、命令、参数、数字、报错原文照抄，不改写、不翻译、不补全、不缩写 |
| 没给到就写「没看到」 | 不许猜行号、耗时、数量、原因 |
| 不写空话 | 不写「已完成」「处理完成」，要写清改了哪个文件的什么、跑了哪条命令、几个通过几个失败 |
| 只看了没改就明说 | 只是读了一下，就写「只是看了看，没有改动」，不编出改动 |
| 前后一个叫法 | 标题里叫「测试脚本」，三行里就别换成「检查程序」 |

再加一张工具名对照（read=看文件内容、write/edit=改文件、bash/pwsh=跑命令、grep=在文件里搜、
glob=按名字找文件、web_search=上网搜、todo_write=列待办），省得它自己瞎猜这个工具在干什么。

解析也放宽了：模型把三行写成「1. 标题：…」「- 标题 …」（带编号、不带冒号）也能认出来，顺手去掉首尾引号——
以前这种写法会让整张牌退化成「这一步的情况」。

**② 删掉没用的声明。**

- 「后面又做了 N 步——没打断你」那条吸顶条和右边「回到最新」按钮，整块删掉；钉住行为本身保留，只是不再吭声。
- 省 token++ 跟两个自动讲冲突时那块黄色框删了。冲突照旧处理（开着批量时两个自动讲直接短路让路），只是不再跳出来解释一遍。
- 顶部状态条在什么自动讲都没开时，也不再常驻「默认只显示原文。点一次才花一次额度…」这句。

**③ 主页一句花销声明。** 过程页最上面常驻一行虚线小字：
「讲解会调模型、花 token：建议用免费或低价模型；高价模型不建议开『自动讲』。」
不隐藏、不弹窗、不用点同意，就摆在那儿。

**④ 浅色模式真的换底色。** 以前浅色/深色只换了一部分颜色变量，面板底色仍可能被宿主或壁纸插件的全局规则盖住，
所以在浅色模式下看着还是深底。现在两档各自一整套调色板：

- 浅色 `#f7f8fb` 底、`#1b1c21` 字；深色 `#15161b` 底、`#e8e9ef` 字。底色和字色直接写在
  `background` / `color` 上并加 `!important`，宿主和壁纸插件都盖不回来；
- 都带 `color-scheme: light / dark`，滚动条、输入框、原生控件跟着一起变；
- 浅色下把卡片、菜单、代码块、翻页按钮的灰底调深一档，不然浅底上几乎看不见；
- 头部、正文、设置页、底栏在浅色下显式透明，深色底不会从缝里透上来；
- （0.4.1 已删除）外观下面原来那两句「只换这个面板的底色和字色……」属于多余声明。

### 5. 讲解风格 / 自己的提示词 / 两档省 token

这三样都在面板设置区的「讲解口味」里。

行尾那枚推荐标签 0.8.0 起回来了（0.4.1~0.7.0 一度没有）。0.4.0 时曾经是：行尾一枚推荐小标签；原来那句解释收进了 hover——
鼠标在标签上停一下就能看，不想看就不占地方。（0.4.1 起「这些开关是干嘛的？」整块说明也删了。）

| 设置 | 一句话作用 | 推荐 |
| --- | --- | --- |
| 讲解模型 | 生成讲解用的模型 | 跟随会话 |
| 思考 | 先自己想一遍再答，更细但更慢更费额度 | 关 |
| 自动弹出 | 一有新一轮就把面板自己弹出来，会打断你 | **关**（想看再点「看过程」） |
| 打开时显示 | 一进来先摆最近多少步 | 8 步 |
| 打开时自动讲 | 打开面板时生成最近几步的讲解（花额度） | 关 |
| 开着就自动讲 | 面板停在过程页时，来一步就自动讲一步（花额度） | **关**（想让它自己讲再开） |
| 省 token++ | 每攒够 N 步才找模型一次，一次讲好几步（真省额度靠它） | 关（开了会提示冲突） |
| 后台跑 | 省 token++ 的附带选项：面板没开也照样攒着讲 | 关（只在面板开着时跑） |
| 总结风格 | 只换说法，不改三行格式 | 通俗 |
| 省 token（精炼） | 最近 N 步先在本机压短再发（不调模型，不花额度） | 开 |
| 提示词 | 看真实提示词 / 写自己的口吻 | — |

**总结风格**：四档预设，只换说法不换格式（永远是「标题 / 在做什么 / 结果」三行）：

| 档位 | 讲出来是什么味 |
| --- | --- |
| 通俗（默认） | 像同事给你顺一遍：它想干嘛、动了哪里、成没成 |
| 专业 | 面向技术负责人，点出机制和判断依据 |
| 一句话 | 只给结论，一行说完 |
| 给新手 | 解释每个名词，假设你不熟这套工具 |

**自己的提示词**：

- 「看当前提示词」→ 预览**真正发出去的两段文本**（系统提示 + 这一步的实际内容）和字数；
- 「新建存档」→ 写要求、起个名字（比如「给老板看」「只要结论」），存成存档；名字随便起，改删都行；
- 存档会出现在风格下拉的「我的存档」里，随时切回内置档；
- 存自己的提示词也不会破格式——插件会把三行格式要求追加在末尾。

**省 token（精炼）：把过程压短后再发给模型**

设置里叫「省 token（精炼）」，旁边就是 N 的输入框（默认 5，可自定义 1–50，另有 3 / 5 / 10 / 20 快捷键）。
打开后：**最近 N 步先在你本机精炼成骨架，再发给模型**。

**精炼不靠模型**——全程本地规则，不调 API、不花额度、也不会编造：

1. **骨架化**：每步压成一行「动作：关键参数 → 结果要点」。工具参数只留最能说明问题的那一个键
   （`file_path` / `command` / `query` 之类），整段 JSON 不进提示词；
2. **抽句**：思考和回答只留带结论味的句子（所以 / 因此 / 根因 / 改成 / 意味着…），不够再补第一句，
   所以「为什么这么改」不会先丢；
3. **实体折叠**：同一个长路径 / URL / 文件名出现两次以上就折成 `#1` `#2`，图例只在最后写一遍。
   路径往往是提示词里最肥的部分，折完通常能省掉一大半；
4. **连续重复折叠**：连着几步干一模一样的事，合成「第 3~7 步（同样的事做了 5 次）」，
   十几次循环读同一个文件只占一行；
5. **降噪**：样板日志行、纯分隔线、超长行先扔掉，报错、数字、结论行优先留。

另外：

- 精炼版开头明写「省 token 模式：最近 X 步已精炼成骨架」，模型知道自己在看骨架，
  缺的信息会直接说看不到，不会瞎编；
- **只有真的更短才用精炼版**：内容本来就短的步骤，精炼版反而更长，插件两种都算一遍，谁短发谁；
- **省了多少你能直接看见**：预览里写「共 X 字 · 不省是 Y 字，实际省了 Z%」，
  每张卡片「展开原文」旁边写「提示词 N 字」；实测肥步骤 4282 → 1233 字（省 71%）；
- 关掉就是原来的完整内容。长会话想省钱就开它。

**外观 / 主题**（设置页最上面）：

| 档位 | 效果 |
| --- | --- |
| 跟随（默认） | 和 DSH 深浅色、以及你装的 dsh-wallpaper 那套插件同步：底色跟着壁纸走，面板是半透明玻璃，换壁纸换色调这里一起变 |
| 浅色 | 固定白底，关掉模糊，字最清楚 |
| 深色 | 固定深底，关掉模糊，夜里不刺眼 |

怎么和壁纸插件配合的：面板优先读壁纸插件的玻璃变量（--we-panel-color / --we-blur / --we-saturate / --we-accent），
读不到就退回宿主自己的令牌（--dsw-alias-*）；固定浅 / 深两档会**就地覆盖**身边这一圈令牌，
所以里面的卡片、按钮、滚动条会一起变色，不会出现「外壳换了、里面还是旧色」的花脸。
没装壁纸插件也能正常用，只是没有玻璃感。

### 4.15 v0.5.0：工具内容不外发（新）

设置页多一个开关 **工具内容不外发**，默认关。

- 关着：和以前一样，工具的参数、返回、报错原文随讲解请求一起发出。
- 开着：请求里只写 `- 读文件 → 成功`（工具名 + 成败），参数、返回、报错原文一个字都不发；提示词里同时写明「参数和返回都没有发送，具体内容不得猜测或补写」，卡片不会出现编造的文件片段或命令输出。
- 「省 token（精炼）」开着时同样生效：精炼版只保留工具名和成败，不再从返回里抽关键行。
- 只影响发出去的内容，本地原文、历史存档、界面显示都不变。

### 4.16 v0.6.0：边生成边显示 + 某一步可以插队（新）

**1）文字是一边生成一边出现的。**

以前点「生成讲解」后卡片一直空着，直到模型把三行全部写完才一次性冒出来。现在模型每吐出一段文字，卡片里就多一段（灰底那小块），三行写完再换成正式卡片。

- 推送走已有的 SSE 通道（`/process-lens/stream`），每个卡片事件多带一个 `draft` 字段；前端节流 120ms 推一次，不会一屏几百帧。
- 生成结束后 `draft` 立刻清空，卡片上只剩解析好的三行，不会留半截文字。
- 「省 token++」合并成一次调用的那种卡也同样边写边显示。

**2）某一步可以设成最高优先级，插到队伍最前面，必要时让它先跑。**

点卡片上的 **优先** 按钮：

- 没在排队的（已生成、失败、空闲）→ 直接排到队首，状态变 `排队中…（第 1 位）`。
- 已经在排队的 → 从当前位置挪到队首，队列里其他人的位置跟着往前补。
- 两个并发槽都占着时 → 取消其中一个**不是优先任务**的请求（它是让位，不算失败，回到队尾重跑），把槽让给这一步。

界面上能看到的排队信息：卡片状态写 `排队中…（第 N 位）`，优先按钮上写 `优先（第 N 位）`。

### 4.17 v0.7.0：存储看得见，也能只删不要的那部分（新）

设置页多一行 **存储**，点右边的 `查看占用` 展开。

**先回答「存在哪儿」。**

| 东西 | 位置 | 会不会自己消失 |
| --- | --- | --- |
| 开关、模型、外观、提示词存档 | 插件目录里的 `process-lens.json`（界面上直接显示完整路径，这台机器是 `C:\Users\<你>\.dsh\process-lens.json`） | 不会，重启后还在 |
| 每条会话的过程记录（每步的思考原文、回答、工具参数与返回、三行讲解） | **只在内存里**，不落盘 | 插件重启或 DSH 重启就没了；重新打开面板会从 DSH 自己的会话记录重新读一遍，不额外调模型 |
| 正在排队 / 正在生成的讲解 | 内存 | 同理 |

所以磁盘上只有那一个 JSON；占内存的大头是过程记录（尤其是一步里塞了几百行命令输出的那种）。

**能清理什么。**

- 提示词存档：每条显示字数，可以单条 `删`，也可以 `全部删掉`。
- 内存缓存：显示「几条会话 · 几轮 · 几步 · 估算大小」，可以按会话单条 `清`，也可以 `全部清掉`。清的是插件自己这份副本，DSH 的聊天记录一条都不动，重新打开面板会自动重建。
- `恢复默认设置`：把上面那个 JSON 退回出厂值（连带清空提示词存档），要点两下——第一下变成 `确定恢复默认？`，4 秒内再点才生效。
- 顶部按钮直接显示合计占用，不用展开也能看出多大。

## 五、实现要点（给以后的自己看）

- **Host 半**：监听 `session/event` 记账（轮次、步骤、工具调用、思考、回答），
  `GET /process-lens/stream`（SSE）推送 `snap` / `card` / `turn` / `ping`；
  `GET|POST /process-lens/api/*` 处理配置、模型目录、轮次定位、快照与讲解请求。
- **原文全文**：`cardOf()` 的 `raw = { thinking, answer, actions[{name,label,detail,args,state,output}] }`，
  文本统一用 `FULL_CHARS = 20000` 截（实际等于不截），`tool.result` 记账时也不再用 `oneLine` 压平，
  只有喂给讲解模型的那份 prompt 才走 `REASONING_CHARS / ANSWER_CHARS / RESULT_CHARS` 的节选。
- **花钱闸门**：`enqueue(sessionId, turn, step, force)`——`force !== true` 时只把状态标 `idle` 并推一帧，
  **绝不排队**。只有 `POST /explain` 走 `enqueue(..., true)`；SSE 连上只算「看」，不算「讲」。
  `/explain` 不传 `step` 时过滤掉 `done / running / queued`。
- **打开时显示 N 步**：`settings.recent`（默认 8，1–100），前端只 slice 后 N 步渲染，另给「展开全部」按钮；
  这是纯前端行为，不影响 host 记账，也不影响讲解。
- **讲解预算**：并发 2，单次 60 秒超时，`maxTokens` 默认 1600；
  `llm.stream` **不能传 `purpose`**（`LlmRequestPurpose` 是 `never`），
  且必须显式取 `resolveModelInfo().reasoning.efforts` 的最低档，否则思考会把预算吃光。
- **历史补账**：第一次被问到某会话时，回放 `session.snapshotEvents()` 末尾 4000 条事件；
  回放期间**不触发**讲解。
- **风格 / 提示词**：风格决定了 system prompt 的人设段（`STYLE_PRESETS`），
  内置格式要求单独放 `OUTPUT_RULES`，无论选哪档、用谁的自定义提示词，
  最后都会把这一段拼上去，所以三行格式不会被玩坏。
  自定义存档存进 settings.prompts（id 用 `p + base36 时间`，name ≤ 40 字，text ≤ 4000 字），
  `activePrompt` 指向哪条就用哪条；删掉当前项会自动回到内置风格。
- **预览**：`GET /process-lens/api/prompt?session=` 直接用 `buildPrompt()` 生成真实内容，
  不是拼一份假的给你看；会话还没步骤时给样例并标 `sample: true`。
- **省 token**：拆成 `buildPromptFull()` / `buildPromptCompact()`，`buildPrompt()` 只在
  `settings.compact === true` 且**精炼版真的更短**时才用它（否则退回完整版，保证不变费）。
  精炼器是纯本地规则，五个零件：`keyParamOf()`（挑一个关键参数）、`interestingLines()`（打分挑报错/数字/结论/首末行）、
  `pickSentences()`（抽结论句，`CONCLUSION_HINT` 决定哪些算结论）、`foldEntities()`（重复长路径折成 `#1` + 图例）、
  以及 `buildPromptCompact()` 里的连续重复折叠（同 head + outcome 的相邻步并成「第 i~j 步」）。
  只有当前这一步才带「它在想 / 它在说」，前面的步只留骨架。
- **注入行清洗**：宿主会往用户消息里塞 `Time sampled while preparing turn…`、`Browser time zone…`、
  `<system-reminder>` 这类系统文本，`cleanUserText()` 按 `NOISE_LINE` 正则整行丢掉，
  （0.4.1 起界面上不再显示「你让它做的」这一行。）
- **字数可见**：`runJob()` 把 `promptText.length` 记到 `entry.promptChars`，`cardOf()` 输出成 `chars`；
  `GET /prompt` 额外算一遍完整版给 `fullChars` 和 `compactUsed`，前端据此显示省了多少 / 是否回退。
- **老会话补齐**：`hydrateTurn(sessionId, turn)` 在完整事件里倒着找这一轮的 `turn/start`，
  从那儿回放到末尾（普通 `hydrate()` 只看末尾 `MAX_REPLAY = 4000` 条）；`deepHydrated` Set 保证每轮只扫一次。
  `/snapshot` 与 `/explain` 都会先调它。
- **显示多少步**：`settings.allSteps`（默认 false）。前端过程页顶部的「最近 N 步 / 全部」直接写这个开关，
  所以选了会记住；`recent` 仍是 N。
- **标签页**：`state.tab`（`'process'` / `'settings'`）放在全局 store 里，切换只换渲染分支；
  过程页那一段外面套了 `.pl-frag { display: contents }`，这样它还是抽屉的 flex 子元素，
  滚动和拉伸跟以前一样。设置页是 `.pl-pane`（`flex:1; min-height:0; overflow:auto`），自己滚，
  所以 `Settings + PromptStudio` 再长也不会被抽屉的 `overflow:hidden` 裁掉——顺手把
  `.pl-pre { max-height: 200px }` 在设置页里放开了。
- **思考开关**：`settings.thinking`（默认 false）。关时 `lowestEffort()` 照旧挑最低档（优先
  none/off/minimal），开时直接返回 undefined 不传 `reasoningEffort`，让模型走自己的默认档；
  同时 `maxTokens` 抬到至少 2400，防止思考把预算吃光、正文被截断。
- **主题**：`settings.theme`（auto / light / dark）由 Host 校验后回传，前端写到抽屉根的 `data-pl-theme`。
  auto 不动任何令牌，只读 `--we-*` 做玻璃；light / dark 在 `.pl-drawer[data-pl-theme=...]` 上覆盖
  `--dsw-alias-bg-*` / `--dsw-alias-label-*` / `--dsw-alias-border-l*` / `--dsw-alias-brand-primary`，
  并把 `--we-blur` 置 0、关掉 backdrop-filter，保证字够清楚。
  0.4.0 起 light / dark 还直接锁死 `background` / `color`（带 `!important`）并设 `color-scheme`：
  `--we-panel-color` 和宿主的全局背景规则都可能盖住变量方案，只有把这两个属性本身钉住，浅色才真的浅。
- **鉴权**：路由统一过 `ctx.get('connection').requestRejection(req)`。
- **设置持久化**：`<DSH_PROFILE_DIR>/process-lens.json`。
